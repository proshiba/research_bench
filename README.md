# research_bench

セキュリティ調査用に別々のリポジトリで作っているアプリを、1 つの画面から横断して扱うためのポータル。

サーバーは立てない。各アプリは静的 JSON を公開し、ポータルはそれを `fetch()` して
手元で索引・結合する。ポータル自身も依存ゼロのバニラ JS で、ビルド工程は無い。

```
  ai-security-analysis ─┐
  vuln-intel-agent     ─┼─→ 各自が静的インデックスを公開 ─→ research_bench が取得・正規化・結合
  threatactor-intel-…  ─┘
```

## 5 つのモード

| | 役割 |
| --- | --- |
| **ダッシュボード** | 入口は速報トップ（各ソースの新着だけを並べた 1 画面）。上部のセレクタで個別アプリの画面へ切り替えると iframe で表示する。アプリ側のタブは残すので、その中を移動できる |
| **クロスサーチ** | 全ソースを横断して IP・ドメイン・ハッシュ・CVE・アクター名などを検索 |
| **ワークベンチ** | 検索結果や手入力を起点にグラフで辿る。選択した値をその場で変換できる |
| **モジュール** | 個別機能を 1 つずつ単体で試す。API の応答をそのまま確かめられる |
| **保存したグラフ** | 調査 API に置いたグラフの一覧。押すとワークベンチに復元する |

同じ実体が複数のソースに現れたとき、ワークベンチでは 1 つのノードに畳まれ、
二重リングと破線のエッジで「ソース横断」であることを示す。これがポータルの中心的な価値。

## 速報トップ

`#/dashboard`（アプリ指定なし）はソースごとのパネルを並べた速報画面。
その日に見るべきものだけを出し、押すとそのアプリのダッシュボードの該当ページへ飛ぶ。

「新しい」と言える手掛かりはソースごとに違うので、パネルごとに取り方を変えている。

| ソース | 新着の基準 | 出しているもの |
| --- | --- | --- |
| デイリーニュース | 記事の日付 | 当日／7 日の切り替え、記事数・タグ付き・登場した CVE、タグ雲、見出し一覧 |
| 脆弱性インテル | CVE の公開日 | 最新日の公開件数・KEV・悪用確認、新しい脆弱性、悪用が確認されているもの（更新の新しい順） |
| アクター情報 | プロファイルの更新日 | アクター数・IOC 数、最近更新されたアクター |
| マルウェア解析 | ケースの初観測 | 解析ケース数・ファミリ数、新しい解析ケース |

ニュースの**見出しにマウスを載せると要約が出る**（キーボードのフォーカスでも出る）。

要約の本来の置き場所は `search.json` の `attrs.概要` だが、載せていないソースもある。
その場合は `apps.json` の `summaries` に別ファイルの場所を書いておくと、**最初に要約が
要求されたときだけ** 1 回取りに行く。トップ画面を開いただけでは取らない。

```jsonc
"summaries": {
  "url":  "data/articles.json",  // site_url からの相対、または絶対
  "list": "articles",            // 配列がある場所
  "key":  "{d}/{i}",             // 1 件から作るキー。entity.detail と突き合わせる
  "text": "s"                    // 要約のフィールド名
}
```

これはポータル側の当て木で、仕様の一部ではない。索引側に要約が入ればそちらが優先される。
取得に失敗したときは吹き出しに理由を警戒色で出し、以後は取りに行かない。

- 日付は今日ではなく **索引の中の最新日** を基準にする（更新が止まっても空にならず、いつのものか分かる）。
- KEV や悪用確認は古い CVE が後から載るので、公開日ではなく更新日で別枠にしている。
- 手掛かりの取り方が未設定のソースは件数だけ出す。日付の当てずっぽうはしない。
- タグ雲を押すとその語でクロスサーチに移る。出しきれない語は「ほか N 種」と断る。

## ワークベンチの読み方

クロームは無彩色に保ち、**色と形は「エンティティ種別」の符号化に予約**している。
出典ソースはサイドバーのメタデータ側で示す。

| 種別グループ | 形 |
| --- | --- |
| IP / エンドポイント | 円 |
| ドメイン / URL | 六角形 |
| ファイル / ケース | 四角 |
| マルウェア / ツール | 三角 |
| アクター | 菱形 |
| 脆弱性 / 製品 | 五角形 |
| キャンペーン / TTP | 角丸四角 |
| その他 | 破線の円 |

色は dataviz の検証器で両モード全ペア判定を通したもの（通常視 ΔE 15.7 / 床 15）。
CVD ΔE は 6–8 の帯に入るため、**形とノード直下のラベルという二次符号化が前提**になっている。
赤系は状態色に予約しているので使っていない。

輪郭と辺で状態を分けている。

- **破線の輪郭** — 索引に裏付けが無い手動ノード（事実と仮説を見分けるため）
- **外側の破線リング** — 複数ソースに畳まれた実体
- **矢羽つきの実線** — 手動リンク

ノードを選んで Ctrl（Mac は Cmd）を押しながら別のノードへドラッグすると、
**自分の推定を手動リンクとして残せる**。「リンクを張る」ボタンからでも張れる。
リンクの名前はサイドバーで直せ、× で消せる。

### まとめて選ぶ

| 操作 | 何が起きるか |
| --- | --- |
| **Shift + ドラッグ** | 矩形で囲んだノードを選ぶ。**今の選択に足す**（囲み直さずに広げられる） |
| **Shift + クリック** | そのノードを 1 件だけ出し入れする |
| **凡例の種別をクリック** | その種別を全部選ぶ。Shift 併用で今の選択に足す |
| **Esc** | 選択を解除する |

Shift 中はノードを掴まないので、**囲んだつもりが 1 件だけ動いて配置が崩れる**ことがない。
囲んでいる最中から選択が反映されるので、離す前に範囲を直せる。

凡例の項目は**その見た目に当たるノードだけ**を選ぶ。`IP / エンドポイント`（丸）を押しても
`AS`（雲）は入らない —— 別の項目として並んでいるものは、選択も別に扱う。
項目には件数が出て、0 件のものは押せない。

選ぶと詳細パネルの上に一括操作が出る（展開・ピン留め・トレイに入れる・値をコピー・削除）。
**その下には主役 1 件の詳細がそのまま残る。**選択中でも 1 件の中身を見たいことが多く、
詳細を隠すと確認のために選択を捨てることになるため。主役は一覧から選び直せる。

選択はグラフの位置やピンと同じく `localStorage` に残る。

## グラフから直接引く

ノードを**右クリック**すると、その種別で意味のある調査だけが並ぶ。結果はその場で
グラフに入る — 分かったことは元のノードの属性になり、新しく分かった実体は
関連ノードとして生える。

| 種別 | 出てくる調査 |
| --- | --- |
| ドメイン | DNS・WHOIS/RDAP・証明書 (CT)・ページ解析・本文取得・ポート・バナー・VirusTotal・urlscan・Censys・隔離ブラウザ |
| URL / Web ページ | DNS・WHOIS/RDAP・証明書 (CT)・ページ解析・本文取得・ディレクトリ探索・urlscan・隔離ブラウザ（URL のみ VirusTotal） |
| IP | ページ解析・ポート・バナー・Shodan・VirusTotal・AbuseIPDB・urlscan・Censys |
| エンドポイント (host:port) | DNS・ページ解析・本文取得・ポート・バナー |
| ハッシュ | VirusTotal |
| すべて | GitHub コード検索・展開・トレイに入れる・リンクを張る・コピー・削除 |

ポート確認とディレクトリ探索は非同期ジョブなので、進捗をステータス行に出しながら待つ。
**失敗したときはステータス行が警戒色になる**（API サーバーの 5xx、CORS、
上流サービスのエラーはそれぞれ違う文言で出る）。

調査で分かった実体は、索引に無くてもグラフに置ける。**色はグループのまま、形で見分ける。**

| 種別 | 形 | 中身 |
| --- | --- | --- |
| **Web ページ** | ブラウザ窓 | 取得した本文・応答ヘッダ・使われている技術・内部パスを属性に持つ |
| **AS** | 雲 | AS 番号がノード、組織名と ISP は属性 |
| **地理** | ピン | 国がノード、地域と都市は属性 |

取り込んだ HTML や WHOIS 全文のような長い属性は畳んで表示し、開くと全文が出る。
これらはリロードしても残る（グラフの状態と一緒に `localStorage` に入る）。

### レート制限

API は悪用防止のため機能ごとに間隔を設けている（**匿名は 5 秒に 1 回、認証済みは
1 秒に 1 回**。Browser Gateway は分あたりの回数）。超えると `429` と
`Retry-After` / `X-RateLimit-Interval` / `retryAfterSeconds` が返る。

**待てば通るものなので、待って自動でやり直す**（最大 3 回）。待っているあいだは
ステータス行に理由と残り秒数を出す — 黙って止まって見えると「壊れた」と思われるため。
それでも通らなかったときだけ警戒色にして、上流サービスのエラーとは違う文言を出す。

ジョブの進捗確認（`action=status`）も同じ制限の対象なので、**ポーリングにも
セッションを付ける**（付けないと匿名扱いの 5 秒制限に当たる）。応答の
`X-RateLimit-Interval` から学んだ間隔より短く叩かないようにもしている。

### 隔離ブラウザ

**Browser Gateway** は Cloudflare 上の Chromium で対象ページを開き、
**画面・描画後 HTML・ページ内リンク**を持ち帰る。**対象ページを自分のブラウザに
読み込ませない**ので、調べたいだけで踏みたくないページに使える。

画面はサイドバーに出る。ただし **`localStorage` には保存しない** —
base64 の PNG は数百 KB あり、数枚で容量上限を食い潰すため。
リロードすると消えるので、必要なら取り直す（`assets/js/view-workbench.js` の
`VOLATILE_ATTRS`）。

### 危険度

AbuseIPDB のスコアと VirusTotal の検知ベンダー数は、**ノード右下の印**とサイドバーの
「危険度」節に出る。生の数字はそのままサイドバーと属性に残る。

提供元ごとに尺度が違う（0–100 の信頼度と、何社が検知したか）ので、**1 つの点数には均さない。**
数字は提供元の単位のまま持ち、グラフの印だけを提供元ごとの境目で段階に落とす。

| 提供元 | 高 | 中 | 低 |
| --- | --- | --- | --- |
| AbuseIPDB（信頼度 0–100） | 80 以上 | 25 以上 | 1 以上 |
| VirusTotal（検知ベンダー数） | 5 社以上 | 2 社以上 | 1 社以上 |

VirusTotal を割合で見ないのは、`5 / 94` が 5% だからといって軽いわけではないため。
1 社だけの検知は誤検知が普通にあるので「低」に落としている。

AbuseIPDB は**通報数ではなく信頼度スコアで判断する**。通報が 97 件あってもスコア 0 という
IP が実在する（1 人が同じ IP を繰り返し通報している場合など）。通報数は属性に残るので、
スコアと食い違っていればそこで気づける。

グラフから引くときは `verbose=true` を付けて通報の明細も取る。**何をして通報されたか**が
スコアの根拠なので、`ポートスキャン 50 / ハッキング 36 / 総当たり 32` のように多い順で属性に入る。
AbuseIPDB は AS 番号を返さない（組織名だけ）ので、ここからは AS ノードを作らない。

印は**警戒色 1 色だけ**を使い、段階は塗り分けで見分ける（種別に使っている色を増やさないため）。

| | 印 |
| --- | --- |
| **高** | 塗りつぶした丸 |
| **中** | 中抜きの丸 |
| **低** | 小さな灰色の点 |
| **検知なし** | グラフには何も出さない。サイドバーには「検知なし」と出る |

複数の提供元が付いているノードは、**いちばん悪い段階**が印になる。
境目は `assets/js/risk.js` の `SCALES` に集めてあるので、そこだけ直せば画面も追従する。

ワークベンチ左端の**調査対象トレイ**に IP・ドメイン・ハッシュを足すとグラフに載る。
索引に見つかればその全ソースの実体が、見つからなければ手動ノードとして置かれる。

入力欄は**複数行をそのまま貼れる**。改行・カンマ・セミコロン・タブで区切り、
箇条書きの記号や番号、前後の引用符は落とす。空白では切らない（`Lazarus Group` の
ように空白を含む名前があるため）。貼ると 1 件ずつのチップになって、追加する前に
何が入るか見える。要らないものは × で外せる。Enter で追加、Shift+Enter で改行。
トレイは折りたためる。トレイとグラフの状態は `localStorage` に保存するので、
別のモードに移ってもリロードしても続きから調査できる。「クリア」で消える。

## グラフの持ち出しと持ち込み

「書き出し」から **Mermaid / STIX 2.1 / PNG**、「読み込み」で Mermaid と STIX を戻せる。

| | 目的 |
| --- | --- |
| **Mermaid** | 持ち出したあとも関係が読める形。種別ごとのノード形と色を `classDef` で埋める |
| **STIX 2.1** | 他ツールに渡す形。`ipv4-addr` / `domain-name` / `file` / `vulnerability` / `intrusion-set` などに対応づけ、辺は `relationship` にする |
| **PNG** | そのままの見た目 |

どちらのテキスト形式にも種別と値を `%% rb:` コメント / `x_rb_*` として残すので、
読み込むと手動リンクまで含めて元のグラフに戻る。これらが無いファイル（他所で書いた
Mermaid）でもラベルから種別を推定して読み込む。STIX の id は値から決め打ちで作るため、
同じグラフを再度書き出しても id は変わらない。

## グラフを保存する

ワークベンチの**右上の「保存」**から、作ったグラフを調査 API の
**STIX ストレージ**（`/api/stix/objects`）に置ける。一度保存すると
ボタンは「更新」に変わり、同じ場所を上書きする。別物として残したいときは
ダイアログの「別のグラフとして保存」を使う。

保存したものは左端の**「保存したグラフ」**に並ぶ。カードを押すと
ワークベンチに戻り、**ノードの配置・ピン・手動リンク・調査対象トレイまで
そのまま**復元する。カード右上の `⋯` から削除できる（取り消せないので一段挟む）。
一覧は**題や説明で絞れる**（サーバー側の `?q=`）。

### 一覧とグラフの行き来

一覧（`#/graphs`）とグラフ（`#/workbench`）は別画面なので、**どちらからも
相手へ行ける入口**を置いてある。

| どこ | ボタン | 何が起きる |
| --- | --- | --- |
| グラフ | **新規調査** | トレイ・グラフ・保存との紐づけを捨てて空にする |
| グラフ | **一覧へ** | 一覧に戻る（今の状態は残る） |
| 一覧 | **新規調査** | 空のグラフでワークベンチを開く |

保存済みのグラフを開いているあいだは、**その題をツール列に出す**。
ステータス行の文言は次の操作で消えてしまうので、「今どれを編集しているか」は
別に常に見えるようにしている。

**「新規調査」は未保存のときだけ 2 回押させる。**1 回目でボタン自体が
「未保存です。もう一度押すと消えます」に変わる。保存済みのものを開いている
ときは API 側に残っているので、確認せずそのまま空にする。

**書き込みと `me` の一覧はログインが必須。**これは API の認証強制フラグとは
無関係で、常に必要（実測で確認）。公開したものの一覧だけは匿名で読める。

### 何がどこに入るか

API は STIX 本体とは別に、**題（`graphTitle`）・説明（`graphDescription`）・
サムネイル（`thumbnail`）**を一次情報として持つ。一覧にも載るので、
**一覧は 1 リクエストで作れる**。

束の中には `report` オブジェクトを 1 つだけ足している。

```jsonc
{ "type": "report", "spec_version": "2.1",
  "name": "APT41 の C2 インフラ",   // 題（束だけ渡しても読めるように）
  "description": "…",
  "published": "2026-07-30T…",
  "object_refs": ["ipv4-addr--…", …],
  "x_rb_graph": { … } }             // 配置・ピン・トレイ（復元用）
```

理由は 2 つ。**`x_rb_graph` を置く欄が API に無い**こと（これが無いと復元が
「STIX の取り込み直し」に落ちて配置が変わる）、そして `report` が 2.1 の正規の
SDO なので**束だけを他の STIX ツールへ渡しても題と説明が読める**こと。

画像は `report` には入れない（API 側と二重持ちになるため）。

| | 上限 | ポータルが送るもの |
| --- | --- | --- |
| STIX 本体 | 10 MiB | 実測 3 KB 前後 |
| サムネイル | 512 KiB | **WebP** 640px・実測 4 KiB（WebP を吐けない環境では JPEG） |
| 題 | 200 文字 | 超えたぶんは切る |
| 説明 | 5,000 文字 | 同上 |

**上限は `/api/meta` から取る。**API の `limits` / `thumbnail` / `pagination` を
起動後に読んでポータル側の既定値を上書きするので、**API 側で変えれば追従する**
（取得に失敗したときだけ既定値のまま動く）。受け付けない画像形式のときは
**画像だけ諦めて本体は保存する** — 保存ごと失敗させない。

画面写真は**今見えているまま**を撮る。全体を写したいときは「全体表示」を
押してから保存する。一覧のカードは切り取らずに全体を出す。

取り込んだ HTML のような長い属性は、保存時に 4,000 文字で切っている。
サイドバーの画面写真（`_shot`）は保存に載せない。

### 絞り込み

一覧の検索欄は**サーバー側の `?q=`** に投げる（題・説明・**STIX の `name`** を横断）。
題を付け忘れた保存も、中身のマルウェア名やアクター名から辿れる。

一覧は `offset` で辿る。応答の `total` と `hasMore` を使い、**何件のうち何件を
出しているか常に断る**（黙って打ち切らない）。続きは「さらに読み込む」で足す。

### サムネイルの取り方

一覧に載るのは画像そのものではなく**取得 URL とメタデータ**。`me` のものは
画像の取得にも `Authorization` が要るので `<img src>` では出せない。
`fetch` で取ってオブジェクト URL にして貼り、入れ替え時に `revokeObjectURL` する。

控えの鍵は **`id:sha256`**（`sha256` は API が返す画像の指紋で、`ETag` と同じ値）。
中身が変わっていなければ**要求そのものが出ない**。中身が変われば鍵も変わるので、
更新した画像は自動で取り直される。

条件付き GET はポータルでは組んでいない。API が `ETag` と `Cache-Control`
（`public` は `max-age=300`、`me` は `private, max-age=0, must-revalidate`）を
付けるので、**ブラウザが `If-None-Match` を付けて 304 に落とす**。
`Authorization` 付きの応答が私用キャッシュに入るか確信が持てなかったので、
実ネットワーク経路で確かめてある（`private` + `Authorization` でも 304 になる）。

連携の記録は
[`docs/agent-prompts/active-research-stix-storage.md`](docs/agent-prompts/active-research-stix-storage.md)。

## モジュール

個別機能は 1 つずつ**モジュール**として数える。左のメニューのモジュールアイコンから
一覧が開き、カードを選ぶとそのモジュールだけの画面になる。ここは
**その機能を単体で試す場所**で、API を叩くモジュールなら要求と生の応答がそのまま見える。

| モジュール | 中身 |
| --- | --- |
| **Shodan 検索** | IP を渡して `/shodan/host/{ip}` を引く。キーは端末の中だけ |
| **Active Research** | 自作の調査 API（[hellow-world](https://hellow-world.hiroshiba.chatgpt.site/api-docs)）の 14 ツール |
| **CyberChef** | 同梱の CyberChef をこの画面の中で開く。値を持ち込める |

どのモジュールでも、結果から取れた値（IP・ドメイン・エンドポイントなど）は
**「送る」でワークベンチの調査対象に積める**。ワークベンチを開いていなくても積んでおけて、
次に開いたときにグラフに載る。モジュール単体の確認とグラフ調査がここで繋がる。

| VirusTotal | `GET /api/tools/virustotal` | トークン必要 |
| AbuseIPDB | `GET /api/tools/abuseipdb` | トークン必要。`verbose=true` で通報の明細 |
| GitHub 調査 | `GET /api/tools/github` | トークン必要 |
| **urlscan** | `GET /api/tools/urlscan` | トークン必要。既存スキャンの検索（新規スキャンは投げない） |

`Web 解析` は API 側で deprecated になったので、ポータルは
`POST /api/request` の `includeAnalyze`（本文で渡す。クエリでは効かない）に移した。
右クリックの項目名は変えていない。

非同期ジョブは start が `job.id` を返し、`action=status&jobId=…` を完了まで叩く形。
ポータルは進捗（走査したポート数やディレクトリ数）を出しながら待ち、途中で中止もできる。

ベース URL は画面で変えられるので、別環境に向けられる。API 側の認証は**今は強制されて
いない**ので、ログインしなくても動く（下記「ログイン」）。
API 側は `Access-Control-Allow-Origin: *` を返すため、中継なしでブラウザから直接呼べる
（`authorization` を許可し、プリフライトに 204 を返すところまで実測済み）。

### ログイン

**`Authorization: Bearer` はこの API のセッション専用**で、外部サービスのキーは
サービスごとの専用ヘッダ（`X-VirusTotal-Key` / `X-AbuseIPDB-Key` / `X-GitHub-Token` …）で渡す。
以前は両方 `Authorization` を使っていたので衝突していた。

セッションは **GitHub ログイン**で得る。OSINT 設定の「調査 API へのログイン」から始まり、
OAuth 2.0 の認可コードフロー + PKCE で交換する。詳細は
[`docs/auth-pkce.md`](docs/auth-pkce.md)。

- **Cookie は使わない。**ポータル（`github.io`）と API（`chatgpt.site`）は別サイトなので、
  セッション Cookie はサードパーティ Cookie になり Safari / Firefox では届かない
- ポータルは静的配信でシークレットを隠せないため、**PKCE のパブリッククライアント**
- 得られるのは**この API のセッションだけ**。GitHub のトークンは API サーバーに留まる
- トークンの置き場所の既定は「このタブだけ」（`sessionStorage`）。
  メモリだけだとリロードのたびにログインし直しになる
- アクセストークンの期限が近ければ**呼び出しの前に取り直す**。
  `401` + `WWW-Authenticate` を受けたときも 1 回だけ取り直して再試行する
- ログイン状態はステータスバーに出る（`調査 API @<名前>`）。失敗時は警戒色

**認証は今のところ強制されていない**（`/api/meta` の `enforcement_enabled` が `false`）。
未ログインでも従来どおり使える。

VirusTotal / AbuseIPDB / GitHub のキーは**トークンが端末の外に出る**ので、画面上でもその旨を
明示している。ブラウザの中だけで済ませたい場合はワークベンチの OSINT タブ（Shodan）側を使う。

## OSINT 連携

ワークベンチの **OSINT タブ**から、選んだノードの値を外部サービスに照会できる。
結果の要約はその場に出て、関連（逆引き・報告された脆弱性など）は
**由来をラベルに残した手動リンク**としてグラフに取り込める。

**ブラウザから直接呼べるのは Shodan だけ。**他はどれも CORS を許可しておらず、
ポータル単体（GitHub Pages の静的配信）からは応答を読めない。実測は次のとおり。

| サービス | 対応する値 | ブラウザから直接 | 実測した CORS の状況 |
| --- | --- | --- | --- |
| Shodan | IP | **可** | 実応答に `Access-Control-Allow-Origin: *` |
| VirusTotal | IP / ドメイン / URL / ハッシュ | 不可 | CORS ヘッダなし |
| ThreatFox (abuse.ch) | IP / ドメイン / URL / ハッシュ / エンドポイント | 不可 | CORS ヘッダなし |
| AbuseIPDB | IP | 不可 | `OPTIONS` が 405・実応答にもヘッダなし |
| urlscan.io | ドメイン / URL / IP | 不可 | プリフライトには `*` が付くが**実応答に付かない** |
| Censys (Platform API) | IP / ドメイン | 不可 | CORS ヘッダなし |

直接呼べないものは 2 通りの扱いにしている。

- **Active Research API 経由で引く**（VirusTotal / AbuseIPDB / urlscan / Censys / GitHub /
  Cloudflare）。トークンがあの API サーバーを通るので、設定画面で節を分けて明示している。
  ワークベンチの右クリックから使う。
- **キーの要らないリンクだけ出す**（ThreatFox など）。「サイトで開く」で該当ページを開く。

**Shodan の API キーはブラウザの外に出ない。**左端の鍵アイコンから入れたキーは
この端末の中だけにあり、送信先は Shodan 本体だけ。

API 経由のトークンは別扱いで、**Active Research API サーバーにサービスごとの
専用ヘッダで渡す**（あちらが各サービスを代理で叩く）。`Authorization` は
あの API 自身のログインセッション専用なので、サービスのキーとは混ざらない。

| 設定項目 | 送るヘッダ |
| --- | --- |
| VirusTotal | `X-VirusTotal-Key` |
| AbuseIPDB | `X-AbuseIPDB-Key` |
| urlscan | `X-Urlscan-API-Key` |
| Censys | `X-Censys-Token` |
| GitHub | `X-GitHub-Token` |
| Cloudflare | `X-Cloudflare-Account-Id` + `X-Cloudflare-API-Token` |

つまりこれらは端末の外に出る。設定画面でも節を分けて明示している。
ブラウザだけで完結させたい場合は入れなければよい。

置き場所は 3 段階から選べる。

| | |
| --- | --- |
| **メモリだけ**（既定） | リロードで消える。最も安全 |
| **このタブだけ** | `sessionStorage`。タブを閉じると消える |
| **このブラウザに保存** | `localStorage`。次回も残る。共有端末では避ける |

### 調査 API に預ける（ログイン時）

ログインしていれば、**API 経由で使うキーを調査 API 側に預けられる**。
設定画面の各キーの下にある「調査 API に預ける」から。預けたキーは
**AES-256-GCM で暗号化して GitHub ユーザーごとに分離保存**され、
一覧・応答・URL のどこにも本文は返らない（末尾 4 文字の目印だけ）。

預けると**その場で端末側からは消す**。残したままだと呼び出しのたびに
専用ヘッダで送ってしまい、**預けた側が使われない**ため
（API の仕様で「ヘッダを明示したらその値を 1 回だけ優先する」）。
以後の呼び出しはヘッダを付けず、`Authorization` だけで通す。

| | |
| --- | --- |
| 預けられる | VirusTotal / AbuseIPDB / urlscan / Censys / GitHub / Cloudflare API トークン |
| 預けられない | **Shodan**（調査 API を通らないので預ける先が無い）、**Cloudflare アカウント ID**（API 側の provider が 1 つで、預けられるのはトークンだけ。ID は秘密ではないので端末に残して毎回送る） |

預けてあるキーは、右クリック調査でもモジュール画面でも**入力欄が空のまま使える**
（モジュール画面では「預け済み」と出て必須が外れる。入れた場合はその値が今回だけ優先される）。
「預けを取り消す」で API 側から消える。

`sessionStorage` / `localStorage` は同一オリジンの別文書からも読める。ポータルは各アプリを
iframe で開いており、GitHub Pages のプロジェクトページは同一オリジンになるので、
既定を「メモリだけ」にしている。

## 動かす

```bash
python3 -m http.server 8000
# → http://localhost:8000/
```

配信物には CI がコミット SHA を `?v=` として付けるので、資産は取り違えない。
ただし `index.html` 自体は GitHub Pages が `max-age=600` を付けるため、更新直後は
古いものを掴んだままになりうる。起動時に配信側の版を見に行き、違っていれば
ステータスバーに「新しいビルド … があります — 再読み込み」を出す。

索引はソース別に遅延ロードする（クロスサーチかワークベンチに入ったとき）。
初回は合計 18 MB 前後を取得するので少し待つ。進捗は下部のステータスバーに出る。

変換モジュールは内蔵の軽量変換（Base64 / Hex / URL / Gunzip / XOR / Strings / Refang /
IOC 抽出 など 19 種）だけで動く。外部依存は無い。

同梱の CyberChef は現在ポータルの UI からは呼んでいない。使うなら単体でビルドして開く。

```bash
cd cyberchef && npm ci && npx grunt prod
```

## 現状

**4 アプリとも spec v1 にネイティブ対応済み。** ポータルは起動時に各アプリの `meta.json` を
読み（`deep_links` と `embed_css` はここから来る）、`search.json` は画面に入ったときに遅延ロードする。

| ソース | エンティティ | search.json |
| --- | --- | --- |
| ai-security-analysis | 1,778 | 0.84 MB (gzip 0.12) |
| vuln-intel-agent | 42,171 | 18.4 MB (gzip 2.26) |
| threatactor-intel-analysis | 17,163 | 3.9 MB (gzip 0.58) |
| tech-memo (daily-news) | 15,249 | 5.3 MB (gzip 0.93) |

合計 76,361 エンティティ。

横串は実データで成立している。マルウェア名の表記ゆれも正規化で吸収する。

| 検索語 | 結果 |
| --- | --- |
| `ShadowPad` | マルウェア解析 + アクター情報 + ニュース |
| `CVE-2021-44228` | 脆弱性インテル + ニュース + アクター情報 |
| `gh0st RAT` | マルウェア解析(`gh0strat`) + アクター情報 |
| `Agent Tesla` | マルウェア解析(`agenttesla`) + アクター情報 |
| `Lazarus` | ニュース + アクター情報 |

デイリーニュースを足したことで、他の 3 ソースのいずれかと繋がる値が **722 件**増えた
（CVE 303・IOC 約 300・アクター 39・マルウェア 18）。ニュースは
「いつ話題になったか」を持つ唯一のソースなので、他の索引にある実体に時間軸が付く。

ワークベンチで `ShadowPad` を 2 段展開すると、
**マルウェア解析の 8 ケース ← ShadowPad → アクター情報の 11 アクター** が 1 枚のグラフになる。

残課題は [`docs/portal-spec.md` §5.1](docs/portal-spec.md) にまとめてある
（脆弱性台帳の優先度が全件 INFO のままなど）。

## IOC をまとめて集める（ブラウザの外）

ポータルとは別に、4 索引から IOC を集めて**実体どうしの重なり**を出すスクリプトが
[`tools/ioc/`](tools/ioc/README.md) にある。Node の標準機能だけで動き、外部 API も
AI も要らない。同じ入力からは同じバイト列が出るので、週次で回して差分を追える。

```bash
node tools/ioc/collect.mjs      # 索引 → iocs / links / entities
node tools/ioc/fetch-asn.mjs    # 経路表の写しを取る（外に出るのはここだけ・キー不要）
node tools/ioc/enrich-asn.mjs   # IP に AS 番号と「その AS の大きさ」を付ける
node tools/ioc/stats.mjs        # → overlaps / graph / 同居の一覧 / stats
node tools/ioc/validate.mjs     # 出来たものを検査する（error があれば終了コード 1）
node tools/ioc/selftest.mjs     # validate 自体を検査する（既知の壊し方 45 通り）
```

いま 19,011 IOC が集まり、**別アクターが同居している /24 が 83 網**。IP に AS を
付けると、**1,024 アドレスしか持たない北朝鮮の AS131279 に APT37 と Lazarus**、
**AS60602 に APT28 と Sandworm** といった組が出る。AS は大きさとアクター数で絞らないと
VPS 事業者の相乗りに埋もれるので、両方で絞ったうえで、除いたほうも
「多くのアクターが借りている事業者」として残している。

API キーは 1 つも要らない。キーの要るエンリッチとピボットは別工程にしてあるので、
キーが無い環境でもここまでは通しで動く。
