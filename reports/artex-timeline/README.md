# ARTEX_TIMELINE

利用者が特定した 2 つの攻撃クラスタについて、AbuseIPDB 上の通報を時系列に並べたもの。

```sh
ABUSEIPDB_API_KEY=k node fetch.mjs   # **ここだけが外に出る**（255 件）
node build.mjs      # 写しから CSV と summary.json。API は呼ばない
node report.mjs     # CSV から日本語レポート
node validate.mjs   # 成果物を読み直して検査（48 項目）
```

| クラスタ | 対象 | 利用者の観測 |
| --- | --- | --- |
| ARTEX | `38.11.173.0/25` と `38.11.221.0/25` の `.1`〜`.125`（250 IP） | ARTEX が起動している |
| sub2api | `198.200.59.85`〜`.89`（5 IP） | sub2api があり、同じリチャージ URL (`198.200.59.85`) がセットされている |

## 能動調査はしない

**対象 IP への接続・走査・認証試行は一切行わない。** ポートスキャンもせず、HTTP も
叩かず、ping も打たない。AbuseIPDB の公開情報と、手元の経路表・索引だけを見る。

## 結論

| 問い | 答え |
| --- | --- |
| ARTEX は通報されるようになったか | **はい。2026-10-14 は 0 / 250、2026-10-30 は 43 / 250** |
| それは複数の観測者が攻撃を見たことか | **いいえ。43 件すべてが単一の通報者** |
| 何として通報されたか | **Exploited Host（カテゴリ 20）だけ** |
| sub2api は | **5 IP のうち `198.200.59.85` だけ**（通報 3 件 / 通報者 3 人） |
| 日本からの通報 | **両クラスタとも 0 件** |
| 2 つのクラスタは繋がるか | **はい。どちらも AS54600 PEG TECH INC** |

## 一番間違えやすいところ

「複数の IP が攻撃元として報告されている」は、**通報の件数ではなく通報者の数**で
見ないと意味を取り違える。

通報 46 件のうち **44 件が単一の通報者**（BR）で、日付以外は同じ定型文、カテゴリも
Exploited Host だけだった。**これは脅威情報フィードの一括登録で、被害者が「攻撃された」
と通報したものではない。**

一括登録を除くと通報は **2 件**しか残らず、**どちらも `198.200.59.85`** への通報。
つまり **ARTEX クラスタ 250 IP には、一括登録以外の通報が 1 件もない。**

### カテゴリ 20（Exploited Host）は攻撃手法ではない

「この送信元自体が侵害されている可能性」を示す補助情報。踏み台にされた正規ホストなら、
送信元の持ち主も被害者である。「この IP が攻撃してきた」とは違う。

### Last observed は独立した時系列情報ではない

定型文に `Last observed <日付> UTC.` が入るが、**通報日と全件一致**していた
（validate が毎回確かめる）。フィード側の観測時刻を別に教えてくれるものではない。

### 定型文を数えるときは日付を畳む

最初の版は本文をそのまま比べたため、`Last observed 2026-10-17` と `2026-10-24` が
別の本文に見え、**44 件 1 人の一括登録を取り逃がした**。日付と数字を `<date>` `<n>`
に畳んでから数える。

## 2 つのクラスタは同じ事業者

利用者の観測（リチャージ URL の共有）とは**独立に**、経路表で繋がった。

```
38.11.173.1    → 38.11.160.0/19   AS54600 PEG TECH INC (US)
38.11.221.1    → 38.11.192.0/19   AS54600 PEG TECH INC (US)
198.200.59.85  → 198.200.32.0/19  AS54600 PEG TECH INC (US)
```

AbuseIPDB は ARTEX 側の ISP を Cogent と答えるが、経路表と VirusTotal は PEG TECH。
食い違いではなく、ARIN RDAP に下位割当（SWIP）の登録が無いため（2026-10-14 に確認）。

sub2api の rDNS は 5 件すべて `visiblooths.net` の下で、`murves` `moxley` `dyres`
`sozel` `olarm` という 5 文字の無意味な名前。**リチャージ URL とは別の筋で同じ持ち主
であることを裏づける。** 一方 ARTEX 側は 250 件すべて rDNS が空。

## 言えないこと

- **ARTEX や sub2api が動いているかは確認していない。** 能動調査をしていないので、
  待ち受けているサービスも見ていない。利用者から渡された前提のまま
- **「攻撃に使われた時期」は特定できていない。** 44/46 件がフィードの一括登録で、
  登録日は攻撃日ではない
- **通報が無いことは無害の証明ではない。** 立てたばかりの基盤や、通報しない被害者しか
  居ない基盤は同じ見た目になる
- AbuseIPDB のカテゴリはレポーターの自己申告
- IP の所在地・ISP・AS は、運用者の国籍や所属を示さない

## 残していないもの

- `reporterId` の値は保存しない（`BR-R01` のような識別子に置換し、同じ人かどうかだけ分かる）
- 通報コメントの原文は保存せず、無害化して短く切ったものと SHA-256 だけ残す
- API キーはコンソール・ログ・CSV・JSON・ソース・エラーにも出さない
- 写し（`.cache/`）は git 管理外
