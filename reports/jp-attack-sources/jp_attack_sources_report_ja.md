## 0b. 「日本からの報告がある」だけでは絞り込みになりません

写しのある **9000 IP のうち 4962 件（55%）に日本からの報告があります**（90 日窓）。

**これは窓のせいだけではありません。** 母集団そのものが絞られています。

```
eligible = Blacklist の上位 10 万件のうち  信頼度 >= 75  かつ
           lastReportedAt が 30 日以内（= 誰かが現に通報している）
```
つまり**構造上ほぼ全部が現役の騒がしい送信元**で、そういう先は日本のセンサーにも引っかかります。
30 日に絞っても 78% 程度しか減りません。

母集団が AbuseIPDB の Blacklist（世界で最も多く通報されている上位）なので、
**通報者が何百人も付いている IP には、まず日本の人も混ざります。**
つまり「日本から報告されている」は、この母集団ではほぼ全部に当てはまり、
**絞り込みの条件として機能しません。** 意味が出るのは次の 2 つを足したときです。

1. **何として報告されたか**（攻撃か、走査だけか、VPN を使っているだけか）

## 4. 日本の観測者の数 — **多いほど重要、ではありません**

観測者数は **45 人で天井**になり、分布はそこへ滑らかに向かいます。

```
上位の値と件数: 45人:1  42人:1  40人:3  39人:4  38人:4  37人:3  36人:1  35人:3  34人:4  33人:5  32人:5  31人:3
```
つまりこの数が測っているのは「どれだけ狙われたか」ではなく、
**「日本にある AbuseIPDB のセンサーのうち何台が見たか」**です。

**45 人ということは「日本のほぼ全センサーが見た」**で、それは
**インターネット全域を騒がしく走査している先**を意味します。標的型の逆です。
実際、観測者数の上位は証拠段階が全件 E0（具体的な攻撃証跡なし）でした。

そこで並び順は**証拠の具体性を観測者数より先に見ています**。
E3/E2 が付いているものはコメントに攻撃の中身が書かれており、そちらが人の確認に値します。

1 人しか見ていない IP は逆に、その 1 人の環境固有の事情かもしれません。
**つまり観測者数は、多すぎても少なすぎても絞り込みに使えません。**

## 10. 偏りと制約

### 母集団の偏り

- **Blacklist が上限で打ち切られています。** スナップショットは 2026-10-26T02:47:59Z 生成の 100000 件
- **候補のうち確認できたのは 9000 件**です。未確認が約 91000 件残っています。
- **既定の選び方は `lastReportedAt` の新しい順**なので、
  **古い報告しか持たない IP は一度も見ていません。** 母集団を広げる日は
  `../global-jp-vuln/build.mjs --new-only` を使います
- したがって件数はすべて**この母集団での数**であり、世界全体の数ではありません

### 分からないものを負に数えていません

- カテゴリの内訳をまだ数えていない IP が **0 件**あります
  （うち日本からの報告があるもの 0 件）。
  これは「攻撃ではない」ではなく**分からない**という意味で、第 2 節の分母から外しています
- 古い写しは脆弱性カテゴリしか残しておらず、DDoS・フィッシング等が見えません。
  引き直した写しだけが段の判定に使えます

### 判定の限界

- **AbuseIPDB のカテゴリはレポーターの自己申告**です。誤分類を含みます
- **段の切り方は決め打ち**です（`tiers.mjs`）。異論がある境目は
  カテゴリ 15（Hacking、範囲が広い）、20（踏み台、被害の印）、14（走査のみ）です
- **1 つの報告に複数のカテゴリが付きます。**段ごとの数は「カテゴリの付与回数」で、報告件数ではありません
- 証拠段階（E0〜E3）は**日本の脆弱性報告のコメントからだけ**取っています。
  DDoS や認証突破しかない IP では空欄になります

### 解釈の注意

- **レポーターが日本に所在することは、日本企業や日本所在システムへの攻撃を意味しません。**
  日本に観測者や監視機器が多いというだけでも同じ結果になります
- **IP の所在地・ISP・ASN は、攻撃者の国籍や所属を示しません**
- 本調査は AbuseIPDB の公開情報のみを使用しています。能動調査は行っていません

### 残していないもの

- `reporterId` は distinct を数えるためだけに使い、値は保存していません
- コメント原文は保存せず、無害化して短く切ったものと SHA-256 だけ残しています
