ペンテスト用ツール ARTEX が動いているとの情報）のレピュテーション調査。


## 能動調査はしない

**対象 IP への接続・走査・認証試行は一切行わない。** ポートスキャンもせず、HTTP も
叩かず、ping も打たない。AbuseIPDB・VirusTotal・公開レジストリの情報だけを見る。

相手は「ペンテスト用ツールが動いている」と言われているサーバで、こちらから触りに行く
理由が無い。**触れば観測ではなく関与になる。**

### 負を出すときに気をつけたこと

負の結果でいちばん危ないのは、**計測器の故障を「汚れが無い」と読むこと**。
そこで次を必ず残す。

1. **分母**。AbuseIPDB を 250/250 引けていること（引き漏らしを「通報なし」に数えない）
2. **対照実験**。同じコード経路・同じ窓で既知の汚い IP を引いて通報が出ること
   （`193.32.204.199` → 通報 5,297 件 / `38.11.173.54` → 0 件）
3. **「通報 0」は無害の証明ではない**という明示。立てたばかりの攻撃基盤は
   まさにこの見た目になる

`validate.mjs` はこの 3 つが成果物に書かれているかまで検査する。

## 唯一の構造的な手がかり — 規則的な格子

VT が 2026-09 以降に初めて項目を作った **15 IP** のホスト番号が
{30,31,32} ∪ {62,63,64} ∪ {94,95,96}（起点 30 / 間隔 32 / 長さ 3）に
**15/15 すべて乗った**。2 つの /24 で同じ番号の並びが出ており、12 件が 2026-10-01。

125 個から 15 個を選んで特定の 9 個組に全部入る確率は無視できるので、
**機械が割り当てた形**である。この 15 件は証明書を 1 つも持たない。

ただし `first_seen_date` は「VT が項目を初めて作った日」であって、**その IP が
動き出した日とは限らない**。別の調査者が同じ日にまとめて照会しただけでも同じ日付に
なる。形が機械的であることは言えるが、原因は決められない。
